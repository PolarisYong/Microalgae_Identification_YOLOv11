全图 + 分块双通道混合推理方案说明

微藻显微图像识别与计数任务 · 推理阶段策略

一、要解决的问题

计数腔室显微图像分辨率为 1224 × 1024 像素，而单个微藻个体直径仅十余至数十像素。YOLO 系列模型在推理时会将输入统一缩放（letterbox）到固定尺寸 imgsz。本项目训练阶段 imgsz 为 896 / 1024，推理阶段降为 640，由此产生两个问题：

  1. 尺度压缩导致细节丢失。整图直接送入模型时，等效缩放系数约为 640 / 1224 ≈ 0.52，微藻直径被压缩到原来的一半左右，边缘与纹理信息在重采样中损失。
  2. 训练—推理尺度失配。训练见到的目标尺度与推理时不一致，密集样本下表现为漏检和相邻个体粘连。

二、基本思路：以分块换取等效放大

不对整幅图做缩放，而是把原图切分为若干保持原分辨率的子块（tile），每个子块单独缩放至 imgsz 后送入模型。子块尺寸越小，模型输入中目标的等效放大倍率越高。

通道送入模型的区域有效尺度相对全图通道放大倍率
全图通道1224 × 1024（整图）0.52×1.00×（基准）
分块 10241024 × 1024 子块0.625×1.20×
分块 512512 × 512 子块1.25×2.40×

有效尺度 = imgsz / max(H, W)。采用 512 分块时，每个微藻在模型输入中的尺寸比全图通道大 2.4 倍，这是小目标检出率提升的直接来源。这也解释了为何本项目中将 TILE_SIZE 由 1024 下调至 512——微藻属小目标，小分块检测更准。

三、为什么是"双通道"而不是只做分块

分块会引入两个副作用，必须由全图通道补偿：

  1. 目标被切碎。跨越分块边界的个体（较大的个体或成团聚集）在任一子块内都只呈现局部形态，模型难以识别。全图通道保留全局上下文，能够完整捕获这类大目标。
  2. 分块可能整体失败。显存溢出（CUDA OOM）或个别子块推理异常时，分块通道可能返回空结果；全图通道提供兜底，保证输出不会全空。

反之，全图通道漏检的小目标由分块通道补齐。二者为互补关系，最终结果取并集，而非二选一。

四、完整流程

图 1　全图 + 分块双通道混合推理流程

步骤 1　图像预处理

LAB 色彩空间 CLAHE 对比度增强（clipLimit = 2.5）+ 非锐化掩蔽（USM）锐化，用于强化微藻边缘与低对比度个体的可辨识度。

步骤 2　全图通道（full pass）

整幅预处理图像直接送入模型，imgsz = 640、max_det = 700、conf = 0.20、iou = 0.45，得到实例集合 A。

步骤 3　分块通道（tile pass）

  • 滑窗切分。步长 step = tile_size − overlap。以 512 / 192 配置为例，1224 × 1024 原图在 x 方向取起点 {0, 320, 640, 712}，y 方向取 {0, 320, 512}，共 4 × 3 = 12 个子块；末尾强制补一个贴边窗口，确保右边缘与下边缘区域不被遗漏。
  • 逐块预测。每个子块单独推理，imgsz = 640、max_det = 500。
  • 坐标回映射。将每个子块检出的掩码与包围盒加上偏移 (offset_x, offset_y)，还原至原图坐标系。

汇总得到实例集合 B。

步骤 4　合并去重

对 A ∪ B 执行迭代式凝聚合并（详见第五节）。

步骤 5　后处理

依次执行：包含关系过滤（去除被大掩码完全包住的小掩码）→ 计数腔室空间区域约束 → 掩码形态精修 → 微小实例过滤（掩码面积 < 10 px）。

五、合并去重算法（本方案关键）

分块的重叠区域会使同一个微藻被相邻子块各检出一次，若不合并即造成重复计数。此处未采用常规的包围盒 NMS，而使用掩码级合并：

  1. 按置信度从高到低排序，取最高者作为合并基准；
  2. 先用包围盒 IoU 快速预筛（为 0 则直接跳过，避免无谓的掩码运算），再在并集包围盒内计算掩码级 mask-IoU；
  3. mask-IoU ≥ 阈值（本项目 0.60）即合并：包围盒取并集、掩码取逻辑或、置信度取算术平均；
  4. 每次合并后重置扫描索引，支持链式合并（A–B、B–C 相继并入同一实例）；
  5. 类别无关（class-agnostic），避免同一类个体因类别预测抖动被拆分。

为何用掩码 IoU 而非包围盒 IoU。微藻形态不规则且在密集区相互毗邻，此时包围盒重叠率很高但掩码本身并不重合。若以包围盒 IoU 判据合并，会把相邻的不同个体错误合并为一个；掩码 IoU 才能准确判断"是否为同一个体"。这是本方案针对实例分割任务做的关键适配。

六、工程鲁棒性设计

  • 三级参数降级。GPU imgsz 640 → GPU imgsz 512 → CPU imgsz 640，任一步失败自动切换下一级。
  • 显存溢出处理。捕获 CUDA OOM 后清空显存缓存并转 CPU 分块；CPU 模式下分块自动收缩为 512 / 128 以降低开销。
  • CPU 兜底重跑。分块通道结果为空且曾发生 OOM 时，以 CPU 模式重新执行分块推理。
  • 合并失败保护。两通道均无检出时抛出明确异常，而非静默返回空计数。

七、与通用方案 SAHI 的关系

SAHI（Slicing Aided Hyper Inference）是社区通用的切片推理库。本项目未引入该依赖，而是实现了等价的自研方案。原因在于本任务需要在标准切片流程之外接入专属环节：掩码级合并（而非常规框级 NMS）、计数腔室空间约束、掩码形态精修、贴边窗口补齐。核心思想与 SAHI 一致，实现针对微藻计数任务做了定制。

八、需要说明的两点

1. 分块配置不可混用。项目内并存两套配置：1024 / 256（有效放大 1.20×）与 512 / 192（有效放大 2.40×）。两者检出的目标尺度差异显著，计数结果不具备直接可比性。任何横向对比实验必须固定同一配置。

2. 合并步骤存在性能瓶颈。当前合并为朴素两两比较，复杂度 O(n²)，且在每次合并后重置扫描索引。在数千实例的极密集图像上耗时明显。若后续需提速，可按空间网格分桶，仅在相邻桶内做 IoU 比较。
